01 — How It Works
1

You buy a policy

Enter your flight number, travel date, and the wallet address that should receive the payout. Pay the 1 pathUSD premium via Tempo MPP or Base x402 (USDC). The policy is created instantly on the server.

2

The checker monitors your flight

Every 5 minutes, a background worker polls AeroDataBox for the live departure status of every active policy. No manual action needed — monitoring starts the moment you buy.

3

Delay detected → payout fires

Once the flight has departed and the recorded delay is ≥ 60 minutes, the payout engine sends 5 pathUSD directly to your wallet via a signed on-chain transfer. No form, no adjuster, no waiting.

payout = premium × 5 multiplier
4

On-time? Policy expires

If the flight departs within the threshold (or the date passes without a delay), the policy moves to expired status. The pool keeps the premium to cover future payouts.

02 — Where the Data Comes From
✈️

AeroDataBox (RapidAPI)

Real-time and historical flight status — departure times, actual vs. scheduled, delay reasons. Queried via a server-side proxy so the API key never reaches the browser.

rapidapi.com/aedbx-aedbx ↗
⛓️

Tempo Blockchain

EVM-compatible L1 for on-chain payout transfers. The pool wallet holds pathUSD and sends transfers via viem + the ERC-20 transferFrom flow. Testnet chainId: 42431.

explore.testnet.tempo.xyz ↗
💳

Tempo MPP

Machine Payments Protocol — HTTP 402 payment gating. The client pays pathUSD and retries with an Authorization credential. Handled by the mppx library.

docs.tempo.xyz/mpp ↗
🔵

Base x402 (optional)

Coinbase's HTTP 402 payment protocol for USDC on Base. Compatible with AI agents using the Base MCP tool. Verified and settled via x402.org/facilitator.

x402.org ↗
03 — Payment Methods
Tempo MPP

pathUSD on Tempo

The primary payment path. Premium is 1.00 pathUSD. Pay using any Tempo wallet or the CLI. The server issues an HTTP 402 challenge; your wallet signs and retries.

Base x402

USDC on Base

Alternative path for AI agents (e.g. Base MCP) or USDC wallets. Send Prefer: payment=x402 to get requirements JSON, then retry with a signed X-Payment header.

06 — FAQ
What counts as a delay?
The actual departure time recorded by AeroDataBox must be ≥ 60 minutes after the scheduled departure. Cancellations are not currently covered (configurable via DELAY_THRESHOLD_MIN).
When does the payout arrive?
The checker polls every 5 minutes. Once a qualifying delay is confirmed, the on-chain transfer is sent immediately — typically within one poll cycle of the delay being recorded.
What is pathUSD?
pathUSD is a USD-pegged stablecoin native to the Tempo blockchain (ERC-20, 6 decimals, contract 0x20c000...0000). You can acquire it via the Tempo testnet faucet or swap on Tempo mainnet.
Can I use this for real flights?
The testnet deployment uses testnet pathUSD (no real value). To go live, deploy to Tempo mainnet (CHAIN_ID=4217), fund the pool wallet with real pathUSD, and set BASE_NETWORK=base for mainnet USDC.
Where is the policy stored?
Policies are stored in an in-memory map and persisted to policies.json on disk. The pool wallet and private key stay server-side; only the payout wallet address is stored per policy.
How do I run it locally?
Copy .env.example to .env, fill in POOL_PRIVATE_KEY, POOL_ADDRESS, and RAPIDAPI_KEY, then run npm run dev. Set DEMO_MODE=true to enable the demo UI.
